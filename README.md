# Mython

**Python 風の文法をもつ静的型付けコンパイル言語**と、その処理系を
**C 言語 + LLVM** でゼロから自作するプロジェクトです。
最終目標は**セルフホスト**（Mython で書いたコンパイラで Mython をコンパイルできる状態）。

```python
def main() -> int:
    print("hello, mython")
    return 0
```

### 言語の機能

```python
import strings                       # モジュール（ch13）

class Node:                          # class とメソッド（ch12）
    v: int
    next: Node | None                # T | None と絞り込み（ch15）

    def init(self, v: int) -> None:
        self.v = v

def main() -> int:
    a: Node = Node(1)
    a.next = Node(2)

    cur: Node | None = a
    while cur is not None:           # 絞り込みは while にも効く
        print(cur.v)
        cur = cur.next               # 代入すると絞り込みは解除される

    xs: list[str] = strings.split("a,b,c", ",")   # 標準ライブラリは Mython 製
    for x in xs:                     # for は while への脱糖（ch11）
        print(x)
    return 0
```

| 段階 | 状態 |
|---|---|
| ① 字句解析 | インデント構文（仮想トークン）・文字列・数値リテラル（10/16/8/2 進） |
| ② 構文解析 | 再帰下降 / 優先順位 8 段 / 脱糖 3 種（`elif`・複合代入・`for`） |
| ③ 型検査 | 静的型・型注釈必須・`T \| None` と絞り込み・モジュールごとの名前空間 |
| ④ コード生成 | LLVM IR（モジュールごとに 1 本の `.ll`）・名前修飾 |
| ⑤ 実行ファイル | clang 連携（`.ll` を並べてリンク） |
| 診断 | 位置・ラベル・note・ヒント / UTF-8 の桁揃え |

## セットアップ

### 必要なもの

- **clang**（macOS なら `xcode-select --install`）
- **make**
- **LLVM**（`opt` / `lli` / `llvm-as` を使うため）

```bash
# macOS
brew install llvm

# Ubuntu / Debian
sudo apt install -y build-essential clang llvm lld
```

詳細は [docs/reference/toolchain.md](docs/reference/toolchain.md)。

### ビルドとテスト

```bash
make            # コンパイラをビルド → build/mythonc
make test       # テストを全部実行
make asan       # AddressSanitizer 付きビルド（メモリバグ調査用）
make info       # ビルド設定を表示
make clean      # 生成物を削除
```

## 使い方

```
mythonc [オプション] <入力.my>

  -o <file>       出力する実行ファイル名（既定: a.out）
  -S              LLVM IR (.ll) を出力して終了
  --dump-tokens   トークン列を表示して終了（字句解析のデバッグ用）
  --dump-ast      AST を S 式で表示して終了（構文解析のデバッグ用）
  --keep-ll       実行ファイル生成後も .ll を残す
  -O0|-O1|-O2|-O3 clang に渡す最適化レベル（既定: -O0）
  -h, --help      使い方を表示
```

### 各段階を覗く

```bash
$ ./build/mythonc --dump-tokens tests/cases/int_42.my
  0  INT       3:1    42
  1  EOF       4:1

$ ./build/mythonc --dump-ast tests/cases/int_42.my
(int 42)

$ ./build/mythonc -S tests/cases/int_42.my
; Generated by mythonc
source_filename = "tests/cases/int_42.my"
target triple = "x86_64-apple-macosx26.0.0"

define i64 @mython_main() {
entry:
  ret i64 42
}

define i32 @main() {
entry:
  %t0 = call i64 @mython_main()
  %t1 = trunc i64 %t0 to i32
  ret i32 %t1
}
```

## テストの書き方

`tests/cases/` に `.my` ファイルを置くだけでテストが増えます。
期待値はファイル先頭のコメントに書きます。

```python
# EXIT: 42
42
```

```python
# ERROR: タブ文字は使えません
	42
```

| 記法 | 意味 |
|---|---|
| `# EXIT: n` | 実行して終了コードが n |
| `# OUTPUT: text` | 標準出力が text（複数行可） |
| `# ERROR: msg` | コンパイルが失敗し、stderr に msg を含む（複数行書くと全部を要求） |
| `# TOKENS: ...` | `--dump-tokens` のトークン種別の並びが一致（複数行は空白で連結） |

```python
# TOKENS: INT NEWLINE INDENT INT NEWLINE DEDENT EOF
1
    2
```

## 設計の要点（なぜこう作るのか）

| 判断 | 理由 |
|---|---|
| **LLVM IR テキストを出力**（C API を使わない） | コードが `printf` だけになり読みやすい。生成物を目で読める。**セルフホストが現実的になる** |
| **全変数を `alloca` に置く**（`phi` を生成しない） | SSA 構築アルゴリズムを回避。LLVM の `mem2reg` が最適な形に直す |
| **型注釈を必須にする**（型推論なし） | 型検査器が「調べるだけ」になり実装が劇的に単純になる |
| **`free()` を呼ばない** | コンパイラは短命プロセス。メモリ管理は独立した大プロジェクト |
| **エラーは最初の 1 件で終了** | エラー回復は独立した難問 |
| **`--dump-tokens` / `--dump-ast` を最初から作る** | 開発速度を決める。**セルフホストの検証にそのまま使う** |

詳細は [docs/design/architecture.md](docs/design/architecture.md) と
[docs/design/ir-conventions.md](docs/design/ir-conventions.md)。

## Python との主な違い

Mython は「Python に似ているが Python ではない」言語です。

| Python | Mython |
|---|---|
| 型注釈は任意 | **必須** |
| `int / int` → float | **エラー**（`//` を使う） |
| `if xs:` が使える | **`if len(xs) > 0:`**（truthiness なし） |
| `a < b < c` | **エラー**（比較連鎖なし） |
| トップレベルに実行文 | **不可**（`main` が入口） |
| `__init__` | **`init`** |
| 継承・例外・lambda | **なし**（v1） |
| 任意精度整数 | **64bit 固定** |

全 15 項目の一覧は [docs/spec/language-spec.md](docs/spec/language-spec.md) 第10節。
