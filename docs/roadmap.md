# ロードマップ — 全20章の地図

全体を 5 部・20 章に分割します。
各章は独立したマイルストーンで、**章の終わりには必ず「前より賢くなった動くコンパイラ」が残ります**。

進捗は「状態」列で管理します（⬜ 未着手 / 🔨 作業中 / ✅ 完成）。

---

## 全体像

```
第I部  電卓を作る          (ch1-3)   ── コンパイラの骨格を通す
第II部 言語らしくする      (ch4-8)   ── 文・変数・型検査・制御構文・関数
第III部 データを扱う       (ch9-12)  ── 文字列・リスト・ループ・クラス
第IV部 実用言語にする      (ch13-15) ── モジュール・標準ライブラリ
第V部  セルフホスト        (ch16-20) ── Mython で Mython を書く
```

---

## 第I部 電卓を作る — コンパイラの骨格を通す

まず「Lexer → Parser → Codegen → LLVM」という**パイプライン全体を最短で貫通**させます。
機能は貧弱でも、端から端までつながっていることが何より重要です。

### ✅ 第1章 環境構築と最小コンパイラ
- **達成目標**: `42` と書いたファイルをコンパイルし、終了コード 42 で終わる実行ファイルを作る
- 学ぶこと: LLVM IR の読み書き / トークン列 / 再帰下降パーサの最小形 / AST / IR 出力
- 成果物: `src/{main,util,lexer,ast,parser,codegen}.c`、`Makefile`、`tests/run_tests.sh`
- [→ 第1章](chapters/ch01-setup-and-minimal-compiler.md)

### ✅ 第2章 四則演算と演算子の優先順位
- **達成目標**: `2 * 3 + (10 - 4) * 6` が正しく計算できる
- 学ぶこと: 演算子の優先順位と結合性 / 文法を階層化する技法 / 単項演算子 / 最長一致
- 成果物: 14 種類の演算子、8 個の文法関数、16/8/2 進リテラル、テスト 34 件
- 注記: `**` は負の指数を実行時エラーにする必要があるため第9章に延期
- [→ 第2章](chapters/ch02-arithmetic-and-precedence.md)

### ✅ 第3章 エラー報告と診断メッセージ
- **達成目標**: 「関連する位置」とヒントを添えた診断を出せるようにする
- 学ぶこと: 診断の3要素 / 循環依存の回避 / 仮想トークンの位置 / UTF-8 の表示幅
- 成果物: `src/diag.{h,c}` 新設、`expect_close()`、テストランナー強化、テスト 36 件
- [→ 第3章](chapters/ch03-diagnostics.md)

```
error: 閉じ括弧 ')' がありません
  --> t.my:2:7
   |
 2 | (1 + 2
   |       ^ ここに ')' が必要です
   |
note: 対応する '(' はここです
  --> t.my:2:1
   |
 2 | (1 + 2
   | ^
   |
   = ヒント: 括弧の対応を確認してください
```

## 第II部 言語らしくする

### ⬜ 第4章 インデント構文（NEWLINE / INDENT / DEDENT）
- **達成目標**: 複数行のプログラムを読み、インデントでブロックを認識できる
- 学ぶこと: オフサイドルール / インデントスタック / 論理行と物理行の違い / 空行とコメントの扱い
- **ここが Python 風言語の一番の山場**です。字句解析器が「仮想トークン」を合成します。

### ⬜ 第5章 変数と型検査パスの導入
- **達成目標**: `x: int = 1` / `x = x + 2` / `return x` が動く。型が合わないとコンパイルエラー
- 学ぶこと: シンボルテーブル / スコープ / `alloca`・`store`・`load` / **意味解析パス（sema.c）の新設**
- 成果物: `src/sema.c` 新規追加。AST に型を書き込む

### ⬜ 第6章 bool・比較演算・論理演算
- **達成目標**: `x < 3 and not flag` が動く。`and`/`or` は短絡評価
- 学ぶこと: `i1` と `i8` の使い分け / 短絡評価のための基本ブロック分岐 / 比較命令 `icmp`

### ⬜ 第7章 制御構文（if / elif / else / while）
- **達成目標**: FizzBuzz が書ける（`print` は暫定実装で可）
- 学ぶこと: 基本ブロック / `br` 命令 / 制御フローグラフ / `break`・`continue` のジャンプ先管理

### ⬜ 第8章 関数定義と呼び出し
- **達成目標**: 再帰でフィボナッチが計算できる
- 学ぶこと: 関数シグネチャの登録（前方参照） / 呼び出し規約 / 引数の `alloca` へのコピー / 戻り値の型検査 / 「全経路で return するか」の検査

## 第III部 データを扱う

### ⬜ 第9章 文字列と C ランタイム連携
- **達成目標**: `print("hello")` / `"a" + "b"` / `len(s)` が動く
- 学ぶこと: グローバル定数の出力 / 文字のエスケープ / **`runtime/runtime.c` の新設** / `extern` 宣言 / `malloc`
- 成果物: `runtime/runtime.c`（`my_print_str`、`my_str_concat` など）

### ⬜ 第10章 list[T]（動的配列）
- **達成目標**: `xs: list[int] = []` / `xs.append(1)` / `xs[0]` / `len(xs)` が動く
- 学ぶこと: ジェネリック型の型検査 / ヒープ上のデータ構造表現 / `getelementptr` / 境界検査

### ⬜ 第11章 for 文と range
- **達成目標**: `for i in range(10):` / `for x in xs:` が動く
- 学ぶこと: 構文糖の脱糖（desugaring）— for を while に書き換える

### ⬜ 第12章 class（構造体とメソッド）
- **達成目標**: `class Token:` にフィールドとメソッドを定義して使える
- 学ぶこと: 構造体型の IR 定義 / フィールドオフセット計算 / `self` の暗黙引数 / コンストラクタ / 名前修飾（マングリング）

## 第IV部 実用言語にする

### ⬜ 第13章 モジュールと import
- **達成目標**: `import lexer` で複数ファイルに分割できる
- 学ぶこと: 複数ファイルのコンパイル / シンボルの可視性 / 名前修飾 / リンク

### ⬜ 第14章 標準ライブラリ
- **達成目標**: 文字列操作・ファイル入出力・`dict` 相当が使える
- 学ぶこと: 言語機能とライブラリの境界線の引き方 / Mython 自身で書けるものは Mython で書く

### ⬜ 第15章 セルフホスト準備（機能棚卸し）
- **達成目標**: 「コンパイラを Mython で書くのに何が足りないか」のチェックリストを完成させ、穴を埋める
- 学ぶこと: ブートストラップの計画立案 / 言語機能の必要十分性の見極め
- 成果物: [design/self-hosting.md](design/self-hosting.md) のチェックリストが全部埋まる

## 第V部 セルフホスト

ここから先は、**同じコンパイラを Mython で書き直す**作業です。
C 版（stage0）が正解を持っているので、常に出力を比較しながら進められます。

### ⬜ 第16章 Mython で字句解析器を書く
- 成果物: `selfhost/lexer.my`
- 検証: 同じ入力に対し、C 版と Mython 版のトークン列が完全一致する

### ⬜ 第17章 Mython で構文解析器を書く
- 成果物: `selfhost/parser.my`
- 検証: AST のダンプ（S 式形式）が C 版と一致する

### ⬜ 第18章 Mython で型検査器を書く
- 成果物: `selfhost/sema.my`

### ⬜ 第19章 Mython でコード生成器を書く
- 成果物: `selfhost/codegen.my`
- 検証: 生成される `.ll` が C 版と一致する

### ⬜ 第20章 ブートストラップと不動点検証
- **達成目標**: セルフホスト達成
- 手順:
  ```
  stage0 (C製)      + selfhost/*.my  →  stage1 バイナリ
  stage1 (Mython製) + selfhost/*.my  →  stage2 バイナリ
  stage2 (Mython製) + selfhost/*.my  →  stage3 バイナリ
  ⇒ stage2 と stage3 が完全一致すれば、不動点に到達＝セルフホスト成功
  ```
- 学ぶこと: なぜ stage1 と stage2 は一致しなくてよいのか / 不動点（fixed point）の意味
